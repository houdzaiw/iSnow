一、需求背景

当前项目已经实现登录、首页、日历、聊天、我的及相关子页面，但视觉仍停留在旧版本。代码中存在颜色、图片路径、样式直接写在页面里的情况，导致整体换肤成本高、容易漏改，也不利于后续设计迭代。

核心判断：Lanhu 可以帮助下载和分析设计资源，但不能独立完成“代码引用自动替换”。本项目需要在 Flutter 中建立公共 token 和资源映射，再统一改造页面。

二、需求目标

目标类型描述衡量指标目标值
视觉还原将一期页面替换为蓝湖新视觉。颜色、icon、间距、圆角、字体、阴影一致度关键 token 优先一致，页面细节后续微调
资源规范蓝湖有切图优先使用蓝湖资源，没有则用 Flutter 内置 icon。资源引用方式页面通过 AppAssets 引用，不直接散写路径
主题体系抽出全局颜色、渐变、间距、圆角、文本和阴影。公共 token 覆盖范围新增 AppTheme 及相关 token 文件
业务稳定除非中文和明显错误文案外，不改业务逻辑。回归结果旧流程和路由保持可用

三、用户与使用场景

角色场景痛点机会点
普通用户登录、记录心情、聊天、查看个人中心旧视觉和新品牌感不一致用粉色、黄色、柔和渐变和心情球强化情绪表达
开发者后续替换资源、调页面样式硬编码和路径散落导致维护困难用公共类降低替换成本
设计/产品检查实现是否贴近蓝湖缺少可追溯的设计 token用资源映射和 token 表提升对齐效率

五、详细方案

功能一：视觉底座与资源治理

交互流程图

flowchart TD A["读取蓝湖一期页面"] --> B["下载实际使用资源"] B --> C{"是否可语义化命名"} C -->|是| D["写入 assets 对应目录"] C -->|否| E["记录待确认名称"] D --> F["生成 AppAssets 映射"] F --> G["抽取颜色、渐变、间距、圆角、字体、阴影"] G --> H["生成 AppTheme"] H --> I["页面统一引用公共 token"]

详细规则

  • 只下载一期实际使用资源，避免 assets 目录膨胀。
  • 蓝湖有切图时优先使用蓝湖资源，缺失时使用 Flutter 内置 icon。
  • 两者都不合适时，用红色 TODO_ICON 占位，并写入待补清单。
  • 新增页面代码不得继续散写核心颜色和资源路径。

功能二：登录注册视觉迁移

交互流程图

flowchart TD A["登录页"] --> B["点击登录"] A --> C["点击注册"] C --> D["填写邮箱和密码"] D --> E{"校验通过"} E -->|否| F["展示错误提示"] E -->|是| G["协议弹窗"] G --> H{"同意协议"} H -->|否| A H -->|是| I["进入首页"] B --> I

详细规则

  • 登录页使用蓝湖柔和背景和胶囊按钮。
  • 注册页文案统一中文，蓝湖中错误的 Register/Login 语义需修正。
  • 协议弹窗需包含服务条款和隐私政策入口。
  • 保留现有登录注册数据流和路由，不新增业务流程。

功能三：首页与捞球弹窗视觉迁移

交互流程图

flowchart TD A["进入首页"] --> B["展示底部 Tab 和首页内容"] B --> C["点击捞一个"] C --> D["展示随机心情卡片弹窗"] D --> E["点击打开"] E --> F["进入心情详情或保留现有打开逻辑"]

详细规则

  • 首页底部 Tab 优先使用蓝湖切图资源。
  • 首页如果存在旧业务列表，保留数据逻辑，只替换卡片、背景、按钮和入口样式。
  • 捞球弹窗保留旧项目触发逻辑，视觉对齐蓝湖卡片和粉色主按钮。

功能四：日历与发布心情视觉迁移

交互流程图

flowchart TD A["日历页"] --> B["月视图"] B --> C["切换月份"] B --> D["展开或折叠"] B --> E["点击加号"] E --> F["选择心情"] F --> G["填写文字或语音"] G --> H{"发布成功"} H -->|否| I["提示失败并允许重试"] H -->|是| J["刷新当天心情记录"]

详细规则

  • 心情图标统一走 AppAssets.mood*，禁止页面拼接散路径。
  • 同一天多条心情时，日历最多叠加展示 3 个。
  • 语音发布保留现有 60 秒逻辑，视觉使用蓝湖粉色语音条。
  • 发布失败要保留输入内容并允许重试。

功能五：聊天与我的视觉迁移

交互流程图

flowchart TD A["聊天 Tab"] --> B["进入会话"] B --> C["发送消息"] C --> D{"可发送"} D -->|否| E["展示失败或不可发送提示"] D -->|是| F["消息入列表"] B --> G["聊天设置"] G --> H["拉黑聊天或免打扰"] I["我的 Tab"] --> J["查看菜单"] J --> K["编辑资料"] K --> L["保存头像、昵称、性别、生日"]

详细规则

  • 聊天气泡、输入框、发送按钮使用粉色主视觉和统一圆角。
  • 聊天设置中的拉黑、免打扰保留旧逻辑，只调整开关视觉。
  • 我的菜单 icon 优先使用蓝湖切图，缺失时使用 Flutter 内置 icon 或红色待补占位。
  • 编辑资料字段保留旧校验和保存逻辑。

七、异常与边界处理

场景处理方式备注
蓝湖缺少切图使用 Flutter 内置 icon；仍不合适则红色 TODO 占位。必须进入待补资源清单
网络异常登录、发布、聊天发送、资料保存均需展示失败提示并允许重试。保留用户输入
文案非中文或明显错误迁移时改为中文和正确语义。只改表现文案，不改业务逻辑
设计稿包含直播间一期不纳入实现。避免扩大范围
页面细节无法一次性像素级还原先以 token 一致作为一期验收标准。后续逐页微调
