PRD v1.0

iSnow 全局视觉体系迁移

本需求用于指导当前 Flutter App 将已有 UI 视觉替换为蓝湖“心情日历白包”新设计，并同步建立可持续维护的颜色、资源、间距、圆角、字体和阴影体系。

项目类型：Flutter 移动端 App
设计来源：Lanhu 项目“心情日历白包”
实施策略：先底层视觉体系，后多页面批量迁移
一期范围：登录、首页、日历、聊天、我的及对应子页面

一、需求背景

当前 Flutter 项目已经实现主要业务页面，但视觉表现与蓝湖新设计存在差距。代码层面也存在颜色、图片资源、文本样式直接分散在页面中的情况，例如页面中直接引用 Color(0xFFF9E707)、assets/calendar/...、assets/tabbar/...。这种实现方式短期能跑通，但当设计体系整体更新时，替换成本高，容易漏改，并且后续维护缺少统一入口。

核心痛点：需要同时解决“视觉还原”和“工程规范”两个问题。只换图片不抽象资源，下一轮还会重复痛；只抽象 Theme 不对齐蓝湖，用户看到的界面仍然不像新版设计。

现状问题

维度当前表现影响
颜色页面中散落硬编码色值，黄色旧主色较多全局换色难，容易出现新旧主题混杂
资源图片按模块分目录，但引用直接写在页面中替换 icon 时缺少统一映射，难以批量管理
组件已有通用脚手架和部分通用组件，但视觉 token 不完整页面间间距、圆角、字体、阴影容易不一致
设计来源蓝湖可提供设计图、切图和 HTML/CSS 分析可作为新视觉依据，但需要人工建立资源语义与代码映射

二、需求目标

目标类型描述衡量指标目标值
视觉还原 以蓝湖“心情日历白包”为基准，替换一期范围内页面的主视觉、主题色、icon、切图、间距、圆角、字体和阴影。 关键页面设计 token 一致度 颜色、资源、字号、圆角、主间距优先达到一致；具体像素级还原在后续页面验收中迭代
工程规范 建立公共视觉体系文件，减少页面内直接硬编码颜色和资源路径。 新增公共类覆盖范围 覆盖 AppAssets、AppColors、AppGradients、AppSpacing、AppRadius、AppTextStyles、AppShadows、AppTheme
资源治理 只下载和接入当前页面实际使用的蓝湖资源，避免 assets 失控膨胀。 资源接入策略 按一期页面最小可用资源集下载，使用语义化命名
逻辑稳定 旧项目业务逻辑保持不变，只允许修正明显错误文案和非中文文案。 业务回归范围 页面路径、数据流、核心交互不因视觉迁移改变

三、用户与使用场景

用户角色具体场景当前痛点产品机会点
普通 App 用户 打开 App、登录注册、浏览首页、记录心情、聊天、查看个人中心 旧视觉与新设计不一致，情绪化、轻量、柔和的品牌感不足 通过粉色、黄色、柔和渐变、心情球资源提升产品识别度和情绪表达
开发者 根据蓝湖更新页面资源、替换 icon、调整样式 资源引用分散，缺少设计 token，维护成本高 建立统一公共类，后续资源替换只改映射和少量组件
设计/产品协作者 检查实现是否符合蓝湖新视觉 无法快速判断代码里的颜色和资源是否来自蓝湖 用语义化 token 和资源映射表建立可追溯关系

阶段用户触点用户行为痛点/情绪产品机会点

聊天互动 消息页、聊天页、聊天设置页 用户发送消息、进入设置、拉黑或免打扰 发送按钮、气泡颜色、开关样式需要和新粉色体系一致 将气泡色、发送按钮、设置开关纳入 AppTheme 和 AppAssets

5.2 资源替换规则

  • 蓝湖有可导出切图或 icon 时，优先使用蓝湖资源。
  • 蓝湖没有对应资源时，使用 Flutter 内置 icon，统一由公共类或公共组件封装，不在页面中散落。
  • 如果蓝湖和 Flutter 内置 icon 都无法表达，先使用红色背景占位，并在资源映射表中标记 TODO_ICON。
  • 只下载一期页面实际使用资源，不全量下载 210 张设计图全部切图。
  • 资源命名采用语义化命名，例如 AppAssets.tabCalendarActive、AppAssets.moodHappy、AppAssets.buttonSend。

5.3 允许调整的内容

  • 明显错误文案可以修正，例如蓝湖注册页按钮显示为 Login 时，应按语义调整为“注册”。
  • 非中文文案可以改为中文，例如 Login、Register、Select Mood、Edit Profile。
  • 业务流程、路由、数据读写、发布逻辑、聊天逻辑保持现有项目逻辑，不因视觉迁移改变。

六、核心操作主线与数据流向

6.1 视觉迁移主线

蓝湖设计稿
  -> 选择一期页面
  -> 获取设计图和切图资源
  -> 资源语义化命名
  -> 写入 Flutter assets
  -> 建立 AppAssets 映射
  -> 抽取 AppColors / AppGradients / AppSpacing / AppRadius / AppTextStyles / AppShadows
  -> 更新 AppTheme
  -> 页面批量引用公共 token
  -> 运行检查和视觉验收

6.2 页面运行主线

主线前置条件页面行为数据流向
登录/注册 用户未登录或登录态失效 展示新视觉登录页，注册时展示邮箱、密码、确认密码和协议确认 输入数据仍走现有登录注册 provider/API；视觉层只替换样式和资源
首页捞球 用户进入首页 展示新背景、新 Tab、捞球入口；完成捞取后展示弹窗卡片 保留现有 capture 数据和弹窗逻辑，只替换卡片、按钮、遮罩和 icon
日历记录 用户进入日历 Tab 展示展开或折叠日历，点击加号选择心情并发布 保留现有 diary entry 模型；心情资源路径改由 AppAssets 提供
聊天 用户进入聊天会话 展示新聊天气泡、输入框和发送按钮；设置页展示拉黑/免打扰 保留现有 chat message 模型和发送逻辑；设置状态按现有实现同步
我的资料 用户进入个人中心 展示头像、昵称、菜单列表和编辑资料表单 保留现有 profile/edit profile 页面跳转和数据更新逻辑

七、工程方案

7.1 建议新增公共文件

文件职责示例内容
lib/theme/app_assets.dart统一管理图片/icon 路径static const tabHomeActive = 'assets/tabbar/home_active.png';
lib/theme/app_colors.dart统一管理颜色primaryPink、brandYellow、textPrimary
lib/theme/app_gradients.dart统一管理渐变登录注册背景、日历背景、按钮渐变
lib/theme/app_spacing.dart统一管理间距xs、sm、md、lg、页面横向边距
lib/theme/app_radius.dart统一管理圆角按钮胶囊圆角、卡片圆角、弹窗圆角

7.2 资源目录建议

保留当前按模块分目录方式，但新增资源应使用新命名规范。若蓝湖下载出的原始文件名不可读，需要在接入时重命名为语义化名称，并在附件中保留映射。

assets/
  base/
  tabbar/
  profile/
  mood/
  home/
  calendar/
  message/

7.3 验收重点

  • 页面中新增代码不再直接写散落颜色和图片路径，优先引用公共 token。
  • 主题粉色、黄色、柔和渐变、浅灰背景、主文本色应与蓝湖设计一致。
  • Tab icon、心情球、发送按钮、加号/发布相关资源优先使用蓝湖切图。
  • 缺失 icon 必须显式红色占位，方便后续补资源，不允许静默遗漏。
  • 迁移后 App 能正常运行，旧业务流程不改变。

八、异常与边界处理

风险说明处理策略
蓝湖切图不完整 部分图标可能不是独立切图，或设计层未标记导出 优先用 Flutter 内置 icon；仍不合适则红色占位并进入待补清单
设计稿和旧逻辑不一致 蓝湖可能包含旧项目没有的直播间或新流程 一期不做直播间；除文案修正外，保持旧逻辑
资源命名冲突 蓝湖中存在多个重名设计图和切图 以模块+语义命名，必要时追加状态，例如 tabCalendarActive
一次性多页面替换引入回归 用户期望集中替换底层资源和主题，再处理多个页面 先完成公共体系和资源映射，再按模块批量改；每个模块完成后运行静态检查
像素级还原成本过高 当前验收重点是 token 一致，不是逐像素完全一致 先保证颜色、icon、间距、圆角、字体、阴影，后续再做页面级微调
