一、需求背景

iSnow 后续会持续根据蓝湖设计稿新增或调整功能。为了让 AI 能在用户提供蓝湖地址和功能描述后自动接入接口，需要把 Nady 项目整理出的接口库存转化为当前项目可执行、可验证、可追溯的接入基准。

当前 iSnow 已有登录、注册、国家码、用户资料页面和部分接口调用雏形，但还没有完全沿用 Nady 的 baseUrl、签名、headers、统一响应结构、token 持久化、联调日志和严格接口证据机制。

首要原则：每个蓝湖功能接入前必须先匹配 nady-api-inventory.md 的明确接口证据。没有证据时停止并向用户确认，不允许自动猜接口后改代码。

功能：接口证据守门

交互逻辑流程图

flowchart TD A["用户提供蓝湖地址和功能描述"] --> B["AI 搜索 nady-api-inventory.md"] B --> C{"是否找到明确接口证据"} C -- "否" --> D["停止改代码并向用户确认"] C -- "是" --> E["输出接口证据表"] E --> F["定位 iSnow 最小改造范围"] F --> G["更新接口层、model、provider、页面状态"] G --> H["运行 flutter analyze 和 flutter test"] H --> I{"验证是否通过"} I -- "否" --> J["根据调试日志修复"] J --> H I -- "是" --> K["交付改动说明和验证结果"]

规则描述

  • 所有蓝湖功能接入前先搜索 nady-api-inventory.md。
  • 证据必须包含 endpoint、method、参数、响应字段，优先包含 API constant、Retrofit method、Facade usage。
  • 证据不足时停止并向用户确认，不通过语义推断直接改代码。

规则描述

  • 国家码来自 /country-list/default-country、/country-list/hot、/country-list/supported。

  • 已存在用户走 /oauth2/login；不存在用户走短信、验证码、设置密码、登录和默认资料流程。
  • 登录成功后保存 oauth-token、pub-uid、userBaseInfo，启动页可恢复登录态。

七、异常与边界处理

场景 触发条件 页面处理 日志与排查
国家码加载失败 /country-list/* 网络或业务失败。 使用兜底默认国家码，国家码弹层展示重试入口。 记录 path、code、message、traceId。
手机号存在性判断失败 /api/user/hasUser 失败或超时。 保留手机号和国家码，提示重试，不自动进入登录或注册。 重点检查 query 参数 phone、areaCode 和签名。
未同意协议 注册或登录提交时协议未勾选。 阻止请求，提示先同意服务协议和隐私政策。 记录本地阻断日志，无接口请求。
验证码错误或过期 /oauth2/verify/code 返回业务失败。 保留手机号和验证码输入，允许重新发送。 脱敏记录 smsCode，保留 traceId。
token 失效 需要登录态接口返回 token invalid、empty 或 timeout。 清理本地登录态，跳转登录页。 检查 oauth-token、pub-uid 注入和本地缓存。
资料保存失败 /api/user/modifyUser 返回业务失败。 保留编辑内容，展示后端 message。 检查 nick、gender、avatar、signature、birth。
头像上传失败 OSS 上传参数不可用或直传失败。 停止保存头像，允许重新选择或重试。 检查上传参数有效期、bucket、domain、path 和最终 URL。

10.2 技术接入补充

  • 当前项目默认 DEV baseUrl 可继续使用 http://simi2.w1.luyouxia.net/simi，后续需支持 QA 和 PROD 配置切换。
  • 公共 headers 需要集中到 HttpDioManager，避免每个 provider 手动拼装。
  • 签名 v/b 必须按 Nady RequestParamsCryptoInterceptor 规则基于真实请求参数生成。
  • 响应解析必须先处理 ServerResponse<T>，不能继续依赖当前 success 字段。
  • 登录态沿用项目风格，建议 SharedPreferences 保存 token/uid 等标量，Riverpod 管理运行时状态。
