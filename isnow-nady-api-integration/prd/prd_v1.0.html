一、需求背景

iSnow 项目后续会持续基于蓝湖设计稿新增或调整功能。为了让 AI 在接到蓝湖地址和功能描述后能快速、严格、可追溯地接入接口，需要把其他项目整理出的 Nady 接口清单转化为 iSnow 可执行的接口接入基准。

当前 iSnow 已有部分登录、注册和接口调用雏形，例如 HttpApi、HttpDioManager、LoginProvider、登录页、注册页和用户资料页，但与 Nady 的统一响应结构、签名规则、登录态持久化、用户资料接口和调试日志要求还没有完全对齐。

核心约束：后续每个蓝湖功能必须先在 nady-api-inventory.md 中找到明确接口证据。找不到证据时停止并向用户确认，不自动改代码。

五、详细方案

5.1 接口证据匹配机制

后续每次用户提供蓝湖地址和功能描述后，AI 必须先完成接口证据匹配，再决定是否改代码。匹配结果至少包含：接口路径、HTTP 方法、Nady API constant、Retrofit method、Facade usage、请求参数、响应字段、当前 iSnow 代码落点。

如果找不到明确接口，AI 必须停止并向用户确认；不得根据字段名或业务语义直接推断并改代码。

5.2 国家码与手机号存在性判断

登录/注册页加载时先请求默认国家码，页面显示默认 dialCode 和 isoCode。用户可从国家码选择器切换国家。用户输入手机号并满足基本格式后，页面立即触发用户存在性判断，进入以下状态：

状态 触发条件 页面反馈 下一步
待输入 手机号为空或格式不足 隐藏判断结果，不显示错误 继续输入
判断中 手机号和国家码有效，debounce 后请求 /api/user/hasUser 手机号输入区或按钮进入 loading，不阻塞国家码切换 等待接口返回
用户存在 data.hasUser=true 展示密码输入和确认按钮 走手机号密码登录
用户不存在 data.hasUser=false 展示注册路径、协议、验证码入口、设置密码入口 走手机号注册
判断失败 网络、签名、参数或后端错误 保留手机号和国家码，展示可重试错误提示 用户手动重试或修改输入

5.3 手机号 + 密码登录

用户存在时，提交手机号、国家码、密码和设备参数到 Nady 登录接口。成功后需要完成四件事：保存 oauth-token、保存 pub-uid、缓存 userBaseInfo、跳转到 /home。失败时展示后端 message，并在日志中保留 traceId。

5.4 手机号注册

用户不存在时，注册主流程为：

国家码/手机号 -> 判断用户不存在 -> 确认服务协议 -> 发送短信验证码 -> 校验验证码 -> 设置密码 -> 登录 -> 写入默认用户资料 -> 进入首页

注册路径必须复用 Nady 的短信、验证码、设置密码和登录接口。默认用户资料通过 /api/user/complete 或登录后资料编辑接口完成，具体调用顺序以联调返回的用户状态为准。若 Nady 返回状态无法判断是否需要完善资料，停止并向用户确认。

5.5 用户资料展示与编辑

字段 Nady 字段 首期权限 页面要求
用户 ID uid 或 userNo 只展示 个人资料页展示，不允许编辑。
手机号 登录账号 code、areaCode，或账号绑定接口返回值 只展示 如果当前资料接口未返回手机号，优先展示本地登录账号。
国家/地区 countryCode、region、areaCode 只展示 按国家码列表映射展示名称；映射失败时展示原始 code。
头像 avatar 可编辑 选择图片后上传，得到 URL，再保存资料。
昵称 nick 可编辑 本地校验非空、长度限制后提交。
性别 gender 可编辑 使用 Nady int 枚举值，UI 映射中文/英文展示。
生日 birth 可编辑 时间戳与日期选择器互转，保存后刷新资料。
个人简介 signature 入参，返回可能为 userDesc 可编辑 保存时使用 signature，展示时优先使用返回的 userDesc。

5.6 原型待补充

本版本先确认业务逻辑和接口接入范围。原型将在下一步骤输出，届时需要覆盖登录存在性判断、注册验证码、资料展示编辑、loading、错误提示、上传失败等关键状态。

六、技术接入说明

6.1 环境与请求基础配置

环境 baseUrl 用途
DEV http://simi2.w1.luyouxia.net/simi 首期默认联调环境。
QA https://www.simijoy.com/simi 测试环境，后续通过配置切换。
PROD https://www.simisoul.com/simi 生产环境，不作为首期默认调试环境。

当前 HttpDioManager 已硬编码 DEV baseUrl，后续应保留默认 DEV，但把环境配置、公共 headers、签名和响应 wrapper 收敛到 HTTP 层，避免每个 Provider 自行拼 header。

6.2 Headers 与签名

类别 字段 规则
基础 Content-Type 固定为 application/json。
登录态 pub-uid、oauth-token 登录后自动注入；未登录接口不注入或为空。
设备与运行时 systemLanguage、timeZone、storeCode、appVersion、appLanguage、x-auth-token、startTime 沿用 Nady 公参；由当前 AppDevice 能力补齐。
签名 v、b v 为时间戳；b 为 GET query 或 POST body/toJson 字段加 v 和 secret 后生成的 MD5 签名。
风险：当前 LoginProvider._getCommonHeaders() 中的 b 来源是 AppDevice.generateSignature()，需要按 Nady 的 RequestParamsCryptoInterceptor 规则改为基于真实请求参数签名，否则联调可能出现签名失败。

6.3 统一响应结构

Nady 大多数接口返回 ServerResponse<T>，字段包括 code、message、timestamp、traceId、data。当前 iSnow 的 LoginResponse 仍按 success/token/data 解析，需要调整为先解析 wrapper，再解析业务 data。

6.4 当前代码最小改造范围

文件/区域 调整方向
lib/manager/http_api.dart 补齐 /api/user/mine、/api/user/modifyUser、/api/user/complete、上传参数接口等常量。
lib/manager/http_dio_manager.dart 集中处理 baseUrl、headers、签名、登录态注入、响应 wrapper、脱敏日志。
lib/classes/oauth/provider/login_provider.dart 保留现有入口，调整参数名和响应解析，增加 hasUser、注册链路状态、token 保存。
lib/classes/oauth/login_detail_page.dart、register_page.dart 接入即时存在性判断、loading、错误提示、协议校验、验证码和设置密码状态。
lib/classes/launch_page.dart 从持久化登录态恢复路由，已登录去 /home，未登录去 /login。
lib/classes/profile/profile_page.dart、edit_profile_page.dart 从真实资料接口读取并展示，编辑后调用 /api/user/modifyUser 并刷新。
lib/manager/providers.dart 沿用 Riverpod 风格补充登录态、用户资料和刷新触发状态；不额外建立独立认证模块目录。

6.5 状态与持久化原则

用户明确要求沿用当前项目已有方案，且不新增独立认证模块。建议原则如下：

  • 简单标量登录态使用 SharedPreferences 保存，例如 oauth-token、pub-uid、登录手机号、areaCode、countryCode。
  • 运行时 UI 状态使用 Riverpod 暴露，例如登录态、国家码列表、资料加载状态、资料保存状态。
  • 结构化离线数据仍按当前项目已有 Isar 风格处理；首期用户资料如果只用于登录态恢复，可先不落 Isar，避免扩大改造范围。
  • Dio 请求时从持久化或运行时状态读取 token/uid，自动注入 oauth-token 和 pub-uid。

8.2 失败排查说明

失败类型 判断依据 处理建议
环境错误 baseUrl 不符合 DEV/QA/PROD，或接口 404。 检查环境配置和 path 是否包含 /simi。
签名失败 后端返回签名、参数校验或鉴权类错误。 检查 v/b 是否按 GET query 或 POST body 真实字段生成。
登录态缺失 需要登录态接口返回 token empty/invalid。 检查 oauth-token 和 pub-uid 是否保存并注入。

响应解析失败 Dart model parse 报错或 success 字段不存在。 先解析 ServerResponse<T> wrapper，再解析 data。
头像上传失败 获取上传参数成功但 OSS 直传失败，或保存 avatar 后不展示。 确认上传参数有效期、domain 拼接、文件 key 和最终 avatar URL。

九、验收标准

  • 登录/注册页能从接口加载默认国家码、热门国家码和支持国家码；接口失败时有可见错误提示和兜底值。
  • 手机号和国家码输入有效后自动判断用户是否存在；判断中、已存在、不存在、失败四类状态均有 UI 反馈。
  • 已存在用户可用手机号 + 密码登录；成功后保存 oauth-token、pub-uid、用户基础资料，并跳转 /home。
  • 不存在用户可完成协议确认、短信发送、验证码校验、设置密码、登录和默认资料写入。
  • 启动页根据真实登录态恢复路由；登出后清理登录态并返回登录页。
  • 个人页展示真实头像、昵称、性别、生日、国家/地区、手机号、用户 ID、个人简介。
  • 编辑资料页可编辑头像、昵称、性别、生日、个人简介；保存成功后刷新展示。
  • 所有首期接口日志均包含脱敏请求摘要、业务 code、message、traceId 和耗时。
  • 单元测试或 Widget 测试覆盖核心成功和失败分支；代码需通过 flutter analyze 和 flutter test。
  • 任一蓝湖功能缺少 nady-api-inventory.md 明确接口证据时，AI 必须停止并询问用户。
