# 版本迭代检查模板

用于从当前版本升级到下一版本，例如 `v1.0` -> `v1.1`。

## 1. 复制文件

- [ ] 复制 PRD：`prd/prd_final_v当前.html` -> `prd/prd_final_v新版本.html`
- [ ] 复制原型：`prototype/prototype_v当前.html` -> `prototype/prototype_v新版本.html`
- [ ] 复制受影响流程图：`flowcharts/*_v当前.mmd` -> `flowcharts/*_v新版本.mmd`
- [ ] 保留旧版本文件，不覆盖、不删除。

## 2. 更新 PRD

- [ ] 更新页面标题和版本号。
- [ ] 更新版本记录表。
- [ ] 更新右上角版本切换下拉菜单。
- [ ] 将所有 iframe `src` 修改为同版本原型文件。
- [ ] 对新增或变更功能补充详细方案、异常边界和验收标准。

## 3. 更新原型

- [ ] 保留 hash 路由能力。
- [ ] 保留 `?focus=feature_id` 专注模式。
- [ ] 新增或修改对应功能视图。
- [ ] 覆盖默认、loading、成功、失败、空状态。

## 4. 更新流程图

- [ ] 更新主流程或对应功能子流程。
- [ ] Mermaid 节点文案避免未转义特殊字符。
- [ ] PRD 内嵌流程图与 `.mmd` 文件保持一致。

## 5. 接口证据检查

- [ ] 每个功能都已在 `nady-api-inventory.md` 找到明确接口证据。
- [ ] 证据包括 method、path、参数、响应字段。
- [ ] 若证据不足，停止并向用户确认，不自动改代码。

## 6. 代码接入检查

- [ ] 按当前项目现状判断最小改动范围。
- [ ] 不新增不必要模块。
- [ ] 页面状态、路由跳转、token 持久化、错误提示、loading、测试用例同步更新。
- [ ] 运行 `flutter analyze`。
- [ ] 运行 `flutter test`。

## 7. 交付说明

- [ ] 列出新增、修改、删除的文档和代码文件。
- [ ] 列出接口证据。
- [ ] 列出验证命令和结果。
- [ ] 列出未完成事项和需要用户确认的问题。
