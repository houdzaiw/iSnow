## 数据和入口

- 房间封面、标题打开房间资料，两个分类支持点击及横向滑动。管理员区域读取当前房间权限。编辑按钮打开现有编辑页，位置入口移入编辑页。独立 Share、房间顶部和 More 的分享继续使用原流程。
- 管理员人数来自现有名单接口。上限读取 RoomInfo.managerMaxNum，缺失时沿用 Nady 的 20。加载或失败时显示破折号，进入名单后返回重新读取人数。
- 开启房间锁先输入四位密码，关闭先确认。操作成功并刷新服务端资料后更新 Switch，取消、失败及重复点击均不会伪造新状态。麦位摘要读取实际模式和数量。
- 公屏头像、在线列表及既有麦位入口共用 RoomUserCard。头像与昵称进入个人主页。非本人可关注、私聊、@、定向送礼，本人保留 Check Profile。右上角更多菜单仅显示当前权限允许的管理动作，动作仍通过原 ViewModel 执行。
- 用户头像框读取 avatarWidget，等级图标和真实数字读取 userLevel，已佩戴勋章读取 userWearMedalVOS，身份铭牌读取 userIdentityAuthenticationList。VIP 和贵族徽章按实际等级展示。未提供的装饰隐藏，加载中使用中性底色，缺失或加载失败使用红色缺省图。
- 历史卡片读取真实封面、创建者昵称/头像、标题和状态。闹钟旁数字读取 subscribeNum。分享按钮复用现有站内 Party 分享，已结束记录也可打开分享面板，点击按钮独立于卡片详情点击。
- 当前 Party 与历史列表保留分页、刷新和错误重试，加载更多沿用 ViewModel 的并发保护与 ID 去重。接口路径和参数维持现有契约。

## Edit info 独立弹层

统一管理入口的 edit 分支打开 `RoomEditInfoSheet`，沿用 `RoomManagementViewModel`、现有选图、上传及 `/api/room/update/info` 请求，不新增接口。`RoomProfileHeader.trailing` 提供可选右侧控件，默认外观不变；本页承载 More → Location，位置二级页返回后保留名称、简介与本地封面草稿。

- 相机来自本稿原始图层 `15457:347946`，下载为 `room_edit_camera.png`，由 `AppAssets.roomEditCamera` 引用。manifest 记录真实导出 URL 和 image_id。返回箭头与历史稿为同一导出，复用 `roomPartyHistoryBack`。更多入口复用已有房间图片。
- 名称上限沿用 30，简介沿用 200，均按 Unicode grapheme 计数，家庭 emoji 计为一个字符。设计稿的 `6/20`、重复的 Room Name 和 `Comfirm` 分别修正为真实计数、Description 和 Confirm。
- 两个字段为浅灰底，名称计数占用独立尾部空间，简介计数位于独立底行，不覆盖输入。表单独立滚动；Confirm 固定在底部安全区上方，键盘出现时面板缩至剩余空间，内容可继续滚动。
- 选图仅展示本地预览，取消不改变已有草稿。Confirm 才执行上传、保存和房间刷新。空名称不可提交；选图和保存期间禁用输入、封面、位置及重复提交，展示加载状态。
- 上传或保存失败保留草稿与本地预览，优先展示服务端错误并滚动到错误区。保存成功关闭编辑层，回到下面的房间资料。返回或外部遮罩关闭丢弃未保存草稿。
- 退房、切房、切账号、角色失去权限时关闭编辑层和所属菜单。上传期间关闭后，迟到结果不得继续提交房间资料；沿用会话代次校验。

编辑页新增 20 项测试，覆盖初始数据、30/200 限制与 emoji、取消选图、本地预览、上传/保存失败与重试、请求契约、重复点击、位置往返、关闭丢弃、会话和权限失效、准备中关闭，以及短屏和键盘。三张独立截图位于 `test/goldens/room_edit_info_lanhu_v1/`，已对照蓝湖人工检查；历史截图保持不变。
