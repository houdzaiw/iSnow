# 房间在线用户数据流

## 接口与模型

- 沿用 Nady 的 `GET /api/room/list/audience`，仅传当前服务端真实 `roomId`。
- 返回 `data` 为完整在线用户数组，每项包含 `userBase`、`roomIdentity`、`silenceEndTime`。
- `RoomUserInfo` 复用项目已有 `BaseUserInfo` 和房间身份枚举，按 UID 去重，保留接口顺序。
- 不能用麦位列表代替在线列表：未上麦的用户也必须展示和计数。

## 单一数据源

`RoomManager` 持有当前房间的完整 `audience` 和加载状态。

1. 进房成功后，和房间详情、麦位列表一起加载在线列表。
2. 房间音乐条使用在线列表前三名的头像及同一份人数。
3. 点击头像区或人数区，通过 root navigator 打开底部在线列表弹框。
4. 弹框的独立 `RoomAudienceViewModel` 复用已缓存的数据，并刷新一次；支持下拉刷新和失败重试。
5. 房间标题人数、在线弹框人数、礼物面板 All Room 数量、送礼控制器人数，都来自 `RoomState.onlineCount`。

在线列表尚未加载成功时，允许暂用房间详情人数。加载成功后，必须使用完整在线列表的长度，包括空列表的 `0`，不能回退到旧详情人数。

All Room 显示的是在线总人数。实际送礼目标人数仍沿用既有 `canSendSelf` 规则，不能因此取消对本人送礼的过滤。

## 实时更新与生命周期

- Nady 的 `RoomAudienceUpdateEvent` 是前三名及总数的更新，不是全量在线列表。收到当前房间事件后重新请求完整列表。
- 同时打开弹框或连续刷新时合并请求；请求中收到新的在线事件，在当前请求结束后补一次刷新。
- 失败保留上次成功列表，不能把网络错误显示成空房间。
- Keep/恢复保留当前房间缓存和 socket 更新，不依赖页面控制器存活。
- Exit 清理列表；晚返回的旧房间请求不能覆盖退出后的状态，重新进入相同 roomId 也必须隔离旧请求。

## UI 与范围

- 音乐条恢复已有 `lanhuRoomMusicIcon` 展示，不再使用房间描述伪装歌曲名称。
- 音乐条接入选歌、播放/暂停和 Agora 房间共享混音，具体流程见 `room_music_flow.md`。
- 在线用户点击后复用现有用户主页路由。
- UI 视觉参数放在 `lib/theme/`；头像使用接口 URL。缺失头像使用红色图片缺省资源，不使用 Flutter `Icon` 或 `Icons.*`。
