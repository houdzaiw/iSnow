# PK 与 Lucky Box 完整流程

## 本轮对照结论

开发前两项已有接口和简化列表，但未达到 Nady 完整体验：PK 缺少房内红蓝比分、多人收起面板及赢家视觉，`pkVisible` 没有实际展示消费者；宝箱缺少到时提示队列和用户主动开箱，发送回执为空仍可能被认为成功。原29项相关测试通过并不能覆盖这些缺口。

本轮参考 Nady 当前可达的设置、房内 PK、结算、幸运宝箱设置／列表／开箱视图。Nady 已注释的全房间 PK 背景不迁移。保留 iSnow 字体、主题、现有房间 Socket／Agora 和礼物接口。

## 分层与入口

- `lib/classes/room/pk/`：类型化用户／比分／贡献数据、Repository、ViewModel、设置、房内展示、结算和动态头像赢家效果。
- `lib/classes/room/lucky_box/`：类型化配置／结果、Repository、ViewModel、发送和列表。
- `lib/classes/room/activities/`：根导航弹层容器、共享图片按钮、现有播放器适配与房间视觉宿主。
- `RoomToolsController` 是唯一工具房间事件入口，继续持有必要快照并向独立 VM 提供更新，不新增 Socket、网络栈或支付库。旧 `room_pk_page.dart`／`room_lucky_box_page.dart` 保留兼容 export。
- More 关闭完成后，从根导航打开设置面板；重复点击合并，异步导航复核房间代次。PK 已在进行时只能查看；设置不会重复开始。房内宝箱图片打开列表，列表只在用户选择到时宝箱后进入开箱。

## PK

1V1 恰好两人、多人至少两人；按 UID 跟踪并重映射真实 micIndex，离麦移除选择，占旧位置的新用户不继承选择。切模式清空选择；默认3分钟，支持3／5／10／20／30／40／50／60。

- `POST /api/room/pk/begin` 保留 `{roomId,duration,pkUserList}`，前两名 identity 为1／2，其余 null。开始成功关闭设置，管理者、选手和当前 PK 在提交前复核。
- `GET /api/room/pk/info` 保留 roomId 与可选 pkId。按 Nady 恢复方式，当前查询有有效 pkInfo 而缺 eventType 时恢复进行中；HTTP 与 Socket 竞争沿用已有快照版本保护。
- `RoomPkInfoUpdate` 更新真实比分；毫秒 countdown 转换剩余时长，最后30秒提供脉冲强调。到时查询一次，不自行判胜或派奖。
- 1V1 展示红蓝用户与比分进度；多人提供迷你／展开面板和安全区域内拖动。收起仅修改本机展示，不调用服务端结束接口。
- 选手头像复用房内用户卡，Pick 复用定向送礼，贡献用户使用真实 contributorList。不会为了测试这些入口实际送礼。
- `POST /api/room/pk/over` 必须确认；失败保持进行中。提前结束不制造赢家。正常结束沿服务端 pkMap 顺序展示结果，首位正分才播放赢家效果；零分显示结果。
- 终态按 pkId 只消费一次，旧 PK 更新不能复活终态。恢复 UI 时不重播已存在的终态，Keep／后台不补播旧赢家。退出或同房重进时按新代次清理选择及旧回调。

## Lucky Box

- 设置每次打开刷新 `GET /api/redPacket/config?roomId=…`；Room=0／World=1，金额读取 goldQuantiry，人数和秒数来自对应配置。换金额重置人数，换类型重置全部选项。失败时旧配置只读，禁止用内置档位交易。
- 规则使用 rulesUrlAr／rulesUrlEn，其他语言回退英文；仅允许有效 HTTP(S) 页面。余额不足打开现有 Wallet，返回刷新且不自动发送。
- `POST /api/redPacket/push` 保留 `{roomId,type,gold,numberOfRecipients,countdown}`。首次说明明确确认才提交；取消、关闭和返回不发送。确认期间禁重复操作但不播放无意义的加载动画。
- 提交前固定参数并再次核对配置及余额。成功必须有有效宝箱 ID，随后刷新列表／钱包并通知既有余额消费者。空回执或不明确结果不自动重发；先通过明确的刷新操作核对状态。
- `GET /api/redPacket/list?roomId=…` 驱动真实倒计时。到时按列表顺序排队；有礼物、连击、PK结算或其他弹层时等待。关闭跳过本轮自动提示，仍允许列表手动打开。
- 展示开箱不代表领取；仅点击 Open 才 `POST /api/redPacket/grab`，只传 luckyBagId。失败可重试，空／异常结果不当作未中奖。count>0 中奖、count<=0 未中奖，结果与操作及宝箱 ID 绑定。
- 约1750ms显示结果，随后保留约3秒再关闭；用户可提前关闭。关闭等待请求时丢弃迟到 UI，但成功领取仍由共享控制器登记并刷新余额，不再次领取同一宝箱。
- Keep／后台释放当前播放器，仅保留有效业务列表；恢复重新查询，不重播旧领奖。退房、切账号和同房重进隔离旧任务。
- 已有宝箱公屏和世界横幅继续由原消费者负责，不建立重复横幅、领奖或进房链路。
