## 1. 需求依据及优先级

1. **功能逻辑以[飞书《第三款母包开发-功能逻辑记录点》][feishu]为准。** 同一事项有多次记录时，以较新的明确规则为准；专项规则优先于通用描述。
2. 下载目录中的[送礼功能需求][local-gift-prd]、[送礼技术设计][local-gift-design]、[全屏动效功能需求][local-effect-prd]、[全屏动效技术设计][local-effect-design]补充飞书未说明的细节。技术设计明确适用于 `maternal_voice`，其类名、网络封装和“未实现项”不能直接当作 iSnow 现状。
3. UI 优先采用用户指定的[蓝湖项目][lanhu]。未定位到独立设计稿的部分，用户已授权参考 Nady；动效优先核对[本地动效目录][local-assets]，不足时使用已核实的 Nady 候选资源。
4. 保留此前确认的 iSnow 能力：用户卡定向送礼、麦下对象、多人选择、背包及全房模式。下载文档中的限制若与这些能力不同，列为契约差异，不直接删除现有功能。
5. 历史 [PRD v1.0][old-prd]、[实现记录][old-implementation]保留原文，用于追溯；与本次依据冲突的规则按本节处理。两份旧文档并非当前功能完成度的唯一依据。

## 2. 如何阅读状态

- **已具备**：存在可追踪的入口及业务实现；不等于所有设备和后端配置都已联调。
- **不完整**：已有能力，但未满足表内明确的规则。
- **缺失**：本轮在相应调用链未找到该能力，不能用现有通用动画替代完整实现。
- **差异待确认**：现有行为与另一客户端文档不同，尚不能判为 iSnow 缺陷。
- P0 / P1 / P2 是建议开发顺序：P0优先保障扣费、调度和资源生命周期；P1补体验与展示；P2处理策略和外围资源。它们不是已批准的排期。

开发前按下表的独立检查项计数，共34项：**5项已具备、20项不完整、6项缺失、3项差异待确认**。这是本次需求范围的盘点，不是整个房间或App的完成率。

| 停止未结算播放Future、重复释放 | 旧stop没有完成挂起的播放Future，并发stop重复调用原生。现在合并stop任务，在真实原生确认后结算对应Future；旧请求不影响新播放。单元与原生停止用例通过。 |
