Product Requirement Document · v1.0

iSnow 切换 Travel 测试环境 API 与启动配置

将 iSnow 当前的固定环境配置和启动页登录态检查，迁移为 travel 项目的测试环境 Bootstrap 启动流程。启动成功后使用服务端返回的公共 API 基地址，保证登录和首页数据请求进入同一套测试环境。

状态：第一版待确认 目标环境：test 范围：启动配置 + 公共 API

一、需求背景

1.1 当前现状

iSnow 当前通过 AppConfig/AppEnv 保存 dev、qa、product 三套固定地址，并由 HttpDioManager 根据本地环境选择固定 baseUrl、签名密钥和通用请求头。LaunchPage 主要负责延迟展示启动页并检查本地登录态，未建立 travel 项目中的服务端启动会话。

travel 项目则由 MaskBuildConfig 提供构建配置，使用 MaskApiClient 请求 Bootstrap 公共入口，解析服务端下发的 API 基地址和初始化路由，再由 TravelAppController 管理启动、登录、client.init 和失败分流。

1.2 需要解决的问题

  • iSnow 的公共 API 地址与 travel 测试环境不一致，无法直接复用 travel 的测试服务。
  • 固定 baseUrl 无法响应服务端 Bootstrap 返回的动态 API 地址。
  • 启动阶段未校验服务端配置完整性，接口地址异常时可能继续使用旧地址。
  • 登录和首页请求缺少“启动配置成功后才能继续”的统一前置条件。
范围边界：本次不迁移 WebSocket、H5、CDN、支付等非公共 API 地址；不重写现有业务页面和数据模型，只适配网络配置、启动流程和必要的配置解析。

五、详细方案

5.1 配置材料迁移

以 travel 项目的 test 环境为唯一来源，建立 iSnow 可读取的测试环境配置层。配置至少包括：环境名、Bootstrap URL、Bootstrap AAD path、Bootstrap kid、RSA 公钥、channel、是否允许 HTTP、路由映射及服务端要求的包身份。

现有 AppEnv 的固定公共 API 地址和固定 secret 不再作为本次启动后的请求来源。为兼容现有业务，网络层可保留现有调用方法，但其底层 URL 必须通过运行时会话解析。

安全约束：公钥可以随构建配置进入客户端；会话密钥、业务 token、签名材料不能写入日志或拼入 URL。所有服务端返回的 URL 必须进行协议、host 和路径校验。

5.2 启动流程迁移

  1. App 启动并展示现有启动页。
  2. 读取设备身份和客户端信息：平台、包名、版本、build number、设备 ID、系统语言、App 语言、渠道和设备品牌等，字段名与 travel 保持一致。
  3. 调用 Bootstrap 公共入口，按 travel 的协议完成请求封装、加密/解密、响应校验和路由解析。
  4. 从响应中取得 API 基地址，检查 scheme、host、部署上下文和 test 环境约束；非法时直接失败。
  5. 保存本次运行会话和公开配置；如果存在本地有效登录态，按 travel 流程继续执行 client.init；没有登录态则进入现有登录页。
  6. 启动流程未成功完成前，禁止登录页和首页发起依赖公共 API 的请求。

5.3 登录和首页请求

登录页面、登录参数、登录响应模型和本地登录态保存逻辑保持 iSnow 现状。网络仓库在发送请求时从启动会话读取动态 API 基地址，不能继续读取 AppEnv.dev/qa/product.baseUrl。

首页加载沿用现有页面和模型；验收时记录请求地址、HTTP 响应、业务 code 和 UI 数据展示结果。若动态地址失效，按统一错误处理提示用户，不自动切换旧地址。

5.4 失败处理

  • Bootstrap 超时、DNS/网络错误：启动页展示可理解的错误提示和 Retry。
  • 配置缺少 API URL、路由、签名材料或公开必要字段：视为配置错误，阻止继续。
  • 返回 API URL 为不允许协议或不在 test 允许范围：视为不安全地址，阻止继续。
  • 已登录会话在 client.init 阶段失效：清理失效会话后回登录页；其他异常仍停留启动失败页。
  • Retry 重新执行完整 Bootstrap 流程，不复用上一次无效的运行时地址。

5.5 页面与原型

第一版高保真原型已生成：打开 prototype_v1.0.html。原型覆盖正常启动、Bootstrap 失败、Retry、登录成功和首页加载成功；右侧状态审查台用于切换状态，不连接真实接口。

专注模式示例：prototype_v1.0.html?sandbox=true&focus=bootstrap#bootstrap-failed。可将 focus 替换为 startup、login 或 home，锁定无关交互区域。

七、异常与边界处理

场景判定用户反馈系统动作
Bootstrap 超时/断网无法拿到有效响应“Unable to initialize service, please try again.” + Retry停留启动页，不发起登录/首页请求
返回 JSON 缺少 apiBaseUrl配置不完整“Service configuration is incomplete.”阻断启动，不使用旧 baseUrl
API 地址协议不允许不符合 test 传输策略“Service address is invalid.”阻断启动并记录脱敏错误类型
路由 token 或加密校验失败服务端配置/客户端材料不匹配“Service initialization failed.”阻断启动，支持重新 Retry
本地登录态失效client.init 返回 token 失效进入登录页清理失效会话，不展示旧首页
登录请求失败业务或网络错误保留现有登录页错误提示保留当前启动会话，允许用户重新登录
首页请求失败公共 API 返回异常保留现有首页错误/空状态不回退旧环境；记录请求阶段

八、数据追踪与埋点

本次不新增用户行为埋点；建议增加 debug/联调诊断字段，便于判断请求是否进入 test 环境：

  • startup_bootstrap_start/success/failure：阶段、耗时、错误类型、环境名。
  • startup_client_init_start/success/failure：是否恢复登录态、结果类型。
  • login_request_result：成功/失败、接口阶段、HTTP 状态和业务 code。
  • home_request_result：成功/失败、接口阶段、数据是否渲染。
日志禁止包含：RSA 私钥、会话密钥、OAuth token、x-auth-token、完整手机号、完整请求体和服务端敏感响应。
